# Qt + Protected SDK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Implement inline, with a fresh final review.

**Goal:** One-click single-workpiece capture/matching with a minimal Qt preview and a developer SDK backed by a compiled core.
**Architecture:** Public `robot_cal_sdk` exposes DTOs, errors and blocking functions; private `robot_cal_core` owns config, devices, collection and cabinet adapter. Qt `view/qt` runs each single capture in a QThread and coalesces preview updates. Only the core owns device connections.
**Tech Stack:** Python 3.11+, NumPy, PyQt6, PyOpenGL; optional Open3D geometry, Cython compiled binary distribution.
**Spec:** `docs/superpowers/specs/2026-11-03-qt-sdk-distribution-proposal.md`, with inherited mode 2 / legacy PLC requirements from the approved original design.

## Global Constraints

- Each Start processes one complete workpiece, then closes devices and returns to idle, retaining preview/result.
- Exit cancels the job, waits asynchronously for resource cleanup and closes the window.
- Public APIs have no Qt dependency; GUI events are delivered on the GUI thread.
- Only mode 2, read-only PLC requests using ChainPulse, no motion/spray commands or other modes.
- User-supplied recognizer/configuration remain intact.
- Ship private implementation as `.pyd`, exclude private source, generated C and debug files from developer bundle.

## Review Focus

- Binary payload containing frame delimiters and split/coalesced TCP responses.
- Stopped or reversed movement, late-starting direction, startup half workpiece and point budget.
- Partial connection failure, cancellation, network/overall deadlines and GUI closing during work.
- GUI retains one result and cannot start overlapping jobs; previews cannot grow the Qt event queue without bound.
- Developer package contains working public code and binary dependencies, no private implementation sources.
