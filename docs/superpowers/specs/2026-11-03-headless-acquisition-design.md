# 完整工件采集与匹配调用接口设计

状态：用户已批准并要求开始实施；2026-11-03。

## 目标与背景

将现有 Python 激光采数软件改为其他开发者可调用的无界面组件。
只保留 `strategy_name = 2`（`complete_workpiece`）的整件采集。
一次调用自动建立 PLC、所配置激光的连接，等待工件正向通过并采集整件，交给匹配器，匹配成功只返回序号。
序号匹配算法与标准样本由用户后续提供，本次提供可替换的匹配器接口。

## 已确认约束

- 提供 Python 函数及命令行入口。
- PLC 扫描位置取自 `ChainPulse`，不是 `AxisList.Pos`。
- 删除 Qt 界面、模式 1/3、运动控制、路径规划及其专用配置、构建依赖和文档。
- 主机不指挥设备运动；外部 PLC/调用系统负责让工件通过激光。
- 保留采集所需位置读取、激光状态检查、坐标转换、滤波、脉冲回绕处理和整件边界判断。

## 方案选择

1. **Python 库 + 命令行**：直接复用 Python 算法，其他语言可启动命令行读取序号，无常驻服务部署要求。用户已选择。
2. HTTP 常驻服务：适合跨语言远程调用，但引入服务生命周期、请求并发与设备占用管理，本次不采用。

## 调用契约

公开 `scan_workpiece(config_dir=None, *, timeout_s=..., ...) -> Workpiece` 与
`acquire_and_match(config_dir=None, *, matcher=None, timeout_s=..., ...) -> str | int`。
具体超时默认值与可选参数由实现者确定并写入 README。

`Workpiece` 是匹配器的稳定输入，包含按方向的 XYZ 点云、同原点时的合并点云、起止脉冲和坐标原点模式。
数组使用 NumPy `N × 3`，单位 mm；Z 沿用完整工件模式的回绕修正及归零规则。
不同原点数据保留各方向坐标，不伪装成一个统一坐标点云。

匹配器是 `matcher(workpiece) -> str | int | None` 的可调用对象；返回 `None` 表示未匹配，抛出明确的未匹配异常。
空字符串、布尔值和其他类型不能作为成功序号。
用户后续可提供模块函数；命令行以 `--matcher package.module:function` 导入。
未配置匹配器时，`acquire_and_match` 在连接设备前报错；开发者可独立调用 `scan_workpiece` 验证采集。
命令行正常匹配时 stdout 只输出一行序号；错误和诊断写 stderr/日志，失败用非零退出码。

## 采集流程和边界

1. 校验配置、模式、匹配器和时间参数；所有路径相对模块位置或显式 `config_dir` 解析，不改变调用者当前目录。
2. 自动连接 PLC 与 SystemConfig 指定的全部激光；配置错误、连接失败须立即传给调用者。
3. 读取 `ChainPulse` 识别正向运动，复用完整工件模式的有效点阈值与连续帧判断。
4. 保留现有首次启动时跳过处于半件状态的防护，以及多方向启动、结束的协调行为；完整记录这些规则。
5. 整件结束后组装一次完整点云，再调用匹配器。不得把超时、设备故障、最大长度截断所得残件交给匹配器作为完整工件。
6. 成功、失败、超时和取消均关闭本次所有连接；一次调用只处理一个完整工件。再次调用重新建立连接。

保留现有采集算法的用途与结果，允许重组模块和移除为 UI、多进程运动管线服务的队列/遥测结构。
为结束阈值保留必要帧缓存，避免重构时意外截掉工件前沿。
设整体等待超时与网络超时，避免无工件/断网无限等待；部分连接成功后失败也必须释放资源。
进程内重复采集请求要明确拒绝设备占用；本次不建设跨机器调度系统。

## PLC 协议

当前源码的 22 轴报文没有 `ChainPulse`，无法支持用户确认的模式 2 数据源。
依据项目 README 的旧完整工件协议恢复接收布局：大端序、206 字节载荷；
`ChainPulse: Int32 @0`、`ChainSpeed: Int32 @4`、`ChainCountMM: Int16 @8`、
`Status: Int16 @10`、`Operate: Int16 @12`、32 组各 6 字节轴状态从偏移 14 开始。
帧头 `02 02 02 02`，帧尾 `03 03 03 03`；TCP 读请求为原有固定 9 字节读命令。
严格校验长度与帧边界，正确处理 TCP 分包和粘包；不把载荷中的帧尾样式字节当成结束。
仅发送读取所需请求，不发送轴目标、使能、喷涂或其他运动报文。
206 字节完整布局源于仓库文档，是本设计的实施依据，尚未经现场抓包验证；设备验收需比对实际 PLC 报文。

## 删除与保留范围

- 删除 `view/`、Qt 入口、UI 控制/遥测、运动规划和模式 1/3 专用代码。
- 删除喷涂分枪/轨迹执行链；它们不是用户后续提供的序号匹配算法。已有可独立复用的几何分区算法和参数可以保留供后续匹配器接入，采集入口不自动运行喷涂处理管线。
- 保留并整理激光解析、坐标变换、采集滤波以及有用的配置读取工具。
- 清理 `requirements.txt`、`setup.py`、部署检查及 README，交付仅支持无界面采集接口的安装与调用说明。
- 采集核心在内存中交付整件点云；移除原 UI 多进程保存链。使用者可通过 `scan_workpiece` 返回值自行保存或接入后续匹配。
- 保留已有采集相关 TOML 现场参数，移除其他模式和喷涂运动参数；`ModeConfig` 只接受整数 2。
- 保留工作区已有的 `CabinetTypeConfig.toml`：它提供型号、外框/内部分区绝对坐标与分轴容差，但尚未发现对应匹配代码；不根据配置擅自实现用户已声明后续提供的算法。

连接/扫描故障、超时、资源释放、匹配成功/失败/未配置、命令行输出契约和无 Qt/运动依赖。

检查已删除模块无残留导入，验证安装与命令行帮助。
交付 README、Python 调用示例、匹配器接入说明及本地任务记录。
